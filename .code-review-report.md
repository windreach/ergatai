## Issues Found

### Medium Severity

#### 1. Blocking I/O in Async Context (monitor.rs:237-320)

**File**: `crates/ergatai-lock/src/monitor.rs`
**Function**: `rollback_file`

**Problem**: 
The `rollback_file` async function performs blocking I/O operations:
- `SnapshotManager::new(project_root)` - Opens git repository (blocking filesystem I/O)
- `snapshot_mgr.read_snapshot(&snapshot_hash)` - Reads git object store (blocking)

These operations run on the tokio runtime and can block the async executor, potentially affecting other concurrent tasks.

**Impact**: 
During file rollback operations (triggered by unauthorized file modifications), the async runtime may be blocked for milliseconds to seconds depending on git repository size and disk speed.

**Fix**:
Wrap blocking operations in `tokio::task::spawn_blocking()`:

```rust
async fn rollback_file(
    lock_manager: &Arc<FileLockManager>,
    project_root: &Path,
    relative_path: &str,
) {
    // ... snapshot hash lookup ...

    let project_root = project_root.to_path_buf();
    let relative_path = relative_path.to_string();
    
    // Wrap blocking git operations
    let snapshot_content = match tokio::task::spawn_blocking({
        let project_root = project_root.clone();
        let snapshot_hash = snapshot_hash.clone();
        move || {
            let snapshot_mgr = SnapshotManager::new(&project_root)?;
            snapshot_mgr.read_snapshot(&snapshot_hash)
        }
    }).await {
        Ok(Ok(content)) => content,
        Ok(Err(e)) => {
            warn!(error = %e, "Failed to read snapshot");
            return;
        }
        Err(e) => {
            warn!(error = %e, "spawn_blocking failed");
            return;
        }
    };

    // ... rest of async file write ...
}
```

**Severity**: Medium
**Category**: Async and Cancellation Safety
